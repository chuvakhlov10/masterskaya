# Мастерская: правила работы с репозиторием

«Мастерская» — React/Vite PWA для учёта работ и заготовок. Этот репозиторий содержит код; рабочие данные и резервные копии живут отдельно.

## Запуск и проверка

- Используй Node.js 22, как в CI. В корне: `npm ci`, затем `npm run check`. Для узкой проверки: `node --test tests/ИМЯ.test.mjs`. Общая проверка запускает тесты, собирает PWA и проверяет пакеты обеих серверных функций.
- Интерфейс можно открыть через `npm run dev`. Для проверки Service Worker собери приложение через `npm run build` и запусти `npm run preview`: сборка формирует версионированный офлайн-кеш. Используй тестовые записи и заглушки шлюзов; не подключай рабочий аккаунт для тестов.
- Для сборки и тестов не нужны рабочий репозиторий данных, серверные секреты и код подключения устройства.

## Что должно сохраняться

- Комментарий к маркировке не меняет остатки. Остатки выводятся из складского журнала и контрольной точки. Добавляй операции с устойчивыми ID; перенос между складами оформляй как `move`. Возврат списанного на склад не создаёт продажу. Не перезаписывай историю и не корректируй остаток вручную поверх журнала.
- Сохраняй последнюю полную, согласованную копию на устройстве. Неполная загрузка, ошибка сети или смесь эпох не заменяют её пустыми данными. Изменения сохраняются локально до отправки; очередь переживает перезапуск. Проверяй отправку после возврата сети и открытия приложения, без дублей при повторе.
- Для конкурентной записи сохраняй чтение, слияние и запись с актуальным SHA. Различай ошибки сессии, конфликт записи и временную недоступность. Не обходи защиту протокола и эпохи. Не очищай кеш, сессию или очередь ради исправления синхронизации.
- Для дохода используй дату самой записи и границу `2026-11-01 00:00 Europe/Moscow`: обычная доля 40% до неё и 45% начиная с неё, заточка 100%, возвраты со знаком минус. Старые месяцы и записи не пересчитываются по новому тарифу при редактировании.

## Как вносить изменения

- Сверь актуальный `main`, проверь рабочее дерево, работай в отдельной ветке. Держи правку по задаче, проверь затронутый сценарий и `npm run check`. Для согласования открой черновик PR, укажи результат и ограничения проверки.
- Слияние в `main` запускает публикацию GitHub Pages. Требуется согласование выпуска. Успешная упаковка функций в Actions не означает, что они установлены на сервере. При выпуске проверь фактически опубликованную версию и нужный сценарий.
- Рабочие записи, фотографии, коды устройств, токены, приватные ключи, дампы и настройки с секретами не добавляй в код, PR и логи. Для обычной разработки используй только этот репозиторий.
- Любые изменения рабочих данных, настроек серверов, архива или восстановления — отдельная задача с явным разрешением. Для склада сначала зафиксируй точный SHA данных, проверь актуальный бэкап и изолированное восстановление, подготовь план и сравнение итогов; проверь повторно перед применением.
